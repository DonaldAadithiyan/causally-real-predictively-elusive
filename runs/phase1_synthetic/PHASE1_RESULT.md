- **`link2_spec`** (= `enrichment_v2 ≥ 1.0`, the criterion the **source document actually specifies** — `causal-predictive-dissociation-experiments.md` §1.3, phase1 task §9): **passes on every seed** (MVDF enrichment 1.2–2.5×).

- **Why `correlated` wins here — a genuine boundary condition on `R_j`, not a pipeline failure.** `pool_PU_corr` = corr(|P_j|,|U_j|) across the pool is **~0.5–0.6** in this DGP, versus **~0.02–0.42 (H1/H1b)** on the real data: here the difficulty role and the prediction role are *entangled* (σ(z), a_z and the μ_z mean-channel all key off the same latent `z`). `R_j = U_j − E[U_j|P_j]` residualizes exactly that shared variance away, so it discounts a feature whose two causal roles are intertwined — while plain correlation, which does no residualization, enriches harder. The regime proxy is also **dense** (MVDF/corr picks fire on ~2–8× the pool-median window count), and correlation screening is strongest on dense, strongly-correlated features (its real-data weakness was the *sparse* regime). This is consistent with the project's thesis: `R_j` targets causal *specificity*, which only helps when difficulty and content roles actually separate — as they do on the real data and, by construction, do not here.

## Stop-rule decision

**Causal → predictive chain (links 1–3): recovered on every seed.** MVDF selection finds features whose intervention `U_j` is correctly signed, whose natural activation tracks the designed-in regime well above the pool baseline (and always as Type B/C, never Type A — a clean confirmation that `R_j`'s causal-specificity selection, not mere content detection, is what is being exercised), and whose natural activation predicts `S_t` out-of-sample (R² 0.26–0.48 across four estimator classes). The pipeline is demonstrably capable of recovering a causal-to-predictive difficulty chain that exists.

**Link 4 (downstream conformal exploitation): mixed (1/3), and diagnosed.** The learned scorer's inconsistency here mirrors the real-data Task G result on data where the upstream signal is known to be present — so it points to the scorer *mechanism*, not the representation. It does **not** by itself license writing the real-data negatives as 'the representation contains no useful information'; it does mean the real-data link-4 failure is not uniquely a real-data or pipeline-bug phenomenon.

**Verdict:** the most damaging reviewer objection — *'maybe your pipeline can't find useful difficulty information at all'* — is **answered**: on synthetic data with a designed-in chain, links 1–3 recover cleanly. The real-data negatives (Task G, H7-A, SLCP — all closed) can be interpreted as a genuine property of the learned representation and of the exploitation mechanisms, not a pipeline artifact. The one caveat to carry into the write-up is that link 4's synthetic behaviour is itself mixed, for the same reason it was on real data.

> Non-goal reminder: this phase does not attempt a fourth exploitation mechanism. Task G / H7-A / SLCP / CQR-PID on real data remain closed.

> **Methodological note for the paper (from correction 3):** a variance-only or weakly-identified latent regime gives an MSE-optimal point-forecaster no incentive to encode it — a synthetic positive control for this kind of pipeline needs a regime that both carries a small conditional-mean signal *and* is genuinely inferable from the input dynamics. This is a generalizable statement about what difficulty an MSE forecaster can causally represent, not a DGP-debugging footnote.
